# Internationalization (i18n)

Software internationalization ensures an application adapts to different languages, regional formatting conventions, and text directions without codebase modifications.

## Locale Resolution & Negotiation

Applications must establish a deterministic resolution hierarchy to determine the user's active locale:

1. **Explicit user preference:** Authenticated profile setting or explicit language picker selection.
2. **URL routing:** Path prefix (e.g., `/en-US/`, `/ja/`) or localized domain (`example.de`).
3. **Persisted client session:** Cookie or `localStorage` key set during a previous visit.
4. **HTTP headers:** `Accept-Language` header from the browser, parsed by quality values (`q=0.9`).
5. **System default:** Application fallback locale (typically `en-US`).

Format all locale identifiers using [BCP 47](https://www.rfc-editor.org/rfc/bcp/bcp47.txt) language tags (`language[-script][-region]`, such as `en`, `pt-BR`, `zh-Hans-CN`, or `ar-EG`).

Synchronize DOM attributes on the document root whenever the locale resolves:
- `<html lang="[bcp47-tag]">`: Informs screen readers and browser spellcheckers of the active language.
- `<html dir="ltr|rtl">`: Dictates root document layout directionality.

## Runtime Formatting via Native `Intl`

Rely on the native ECMAScript Internationalization API ([ECMA-402](https://tc39.es/ecma402/)) rather than bundling ad-hoc formatting utilities:

- **Dates and Times (`Intl.DateTimeFormat`):** Never output hardcoded timestamp formats like `MM/DD/YYYY`. Formats must reflect regional conventions, 12-hour vs. 24-hour clocks, and explicitly declared IANA time zones (`timeZone: 'UTC'` or `timeZone: 'Europe/Paris'`).
- **Numbers and Currencies (`Intl.NumberFormat`):** Format currencies using standard ISO 4217 codes (`style: 'currency', currency: 'EUR'`). This handles decimal commas vs. periods, thousands grouping, and negative number formatting according to [Unicode CLDR](https://cldr.unicode.org/) rules.
- **Relative Time (`Intl.RelativeTimeFormat`):** Format humanized dynamic timestamps ("3 minutes ago", "in 2 days") natively without third-party date bloat.
- **Collation and Sorting (`Intl.Collator`):** Sort user-facing lists using locale-aware collation (`Intl.Collator(locale, { numeric: true }).compare`) to correctly handle diacritics, natural number ordering ("item 2" before "item 10"), and language-specific alphabetical sequences (such as German umlauts, Spanish `ñ`, or Swedish `å`/`ä`/`ö`).
- **Lists (`Intl.ListFormat`):** Format enumerations ("apples, oranges, and bananas") with grammatical conjunctions tailored to the active locale.

## Pluralization & Message Grammars

- **Multi-Category Plurals:** Languages do not follow a simple binary singular/plural rule. Arabic requires six forms (`zero`, `one`, `two`, `few`, `many`, `other`); Slavic languages (Russian, Polish, Czech) have distinct forms based on numeric modulos. Evaluate plurals using `Intl.PluralRules` or ICU MessageFormat syntax:
  `{count, plural, one {# item} few {# items} other {# items}}`
- **Zero Concatenation:** Never construct messages by concatenating string fragments (e.g., `"Delete " + count + " " + itemType`). Word order, grammatical case, and adjective-noun agreement vary across languages. Use token replacement with named variables.
- **Gender & Select Rules:** Use selector-based formatting for messages depending on gender or grammatical context:
  `{gender, select, female {She updated her} male {He updated his} other {They updated their}} profile`

## Right-to-Left (RTL) Layout Architecture

Supporting bidirectional scripts (Arabic, Hebrew, Persian, Urdu) requires structural separation of direction:

- **CSS Logical Properties:** Use logical properties rather than physical sides:
  - `margin-inline-start` / `margin-inline-end` instead of `margin-left` / `margin-right`.
  - `padding-inline`, `padding-block`, `inset-inline` instead of physical top/left/right/bottom.
  - `text-align: start` / `end` instead of `left` / `right`.
- **Directional Iconography:** Directional indicators (breadcrumbs, chevron navigation, back/forward buttons) must flip in RTL. Universal symbols (video player controls, search magnifying glasses, checkmarks) and physical meters must not flip.
- **Bidirectional Isolation:** Isolate untrusted or user-generated multilingual text using the `<bdi>` tag or CSS `unicode-bidi: isolate` to prevent embedded LTR tokens (e.g. phone numbers or URLs) from corrupting surrounding RTL sentences.
- **Script Font Fallbacks:** Define system font stacks that gracefully cascade to non-Latin scripts (e.g. `system-ui`, Arabic Naskh, CJK sans-serif) without Flash of Unstyled Text (FOUT).

## String Extraction & Translation Pipeline

- **Message Catalogs:** Store user-facing copy in structured message catalogs (JSON, PO, XLIFF). Keep translation keys semantic and hierarchical (`auth.login.submit_label`) or content-hashed.
- **Automated Extraction:** Run extraction tools (such as formatjs CLI or i18next-parser) during CI builds to catch unextracted strings, unused keys, and untranslated tokens before merging.
- **Pseudo-Localization:** Test UI layout resilience against string expansion (German and French often expand by 30%) and unextracted strings by rendering pseudo-localized strings (e.g., `[~Àççéñtéd Têxt~]`) in staging environments.
- **Context for Translators:** Supply developer descriptions, variable explanations, and character limit constraints in translation metadata to prevent mistranslation of homonyms (e.g., "Run", "Book", "Close").

## Checklist

- [ ] Locale resolution follows an explicit hierarchy: user profile > URL route > session/cookie > `Accept-Language` > default.
- [ ] Root `<html>` element dynamically receives matching `lang="[bcp47]"` and `dir="ltr|rtl"` attributes.
- [ ] Dates, times, numbers, currencies, and relative intervals are formatted via native `Intl` APIs without hardcoded formats.
- [ ] Lists and string arrays are sorted using `Intl.Collator` rather than default JavaScript array `.sort()`.
- [ ] All pluralization handles multi-form rules via `Intl.PluralRules` or ICU MessageFormat syntax rather than `count === 1` checks.
- [ ] No user-facing text is constructed via string concatenation; all messages use parameterized token interpolation.
- [ ] Layout stylesheets use CSS Logical Properties (`margin-inline-start`, `text-align: start`) instead of physical directions.
- [ ] Navigational icons flip in RTL mode while media controls and universal symbols remain untransformed.
- [ ] Multilingual user inputs and mixed-direction strings are wrapped in `<bdi>` or `unicode-bidi: isolate`.
- [ ] Typography stacks define fallback fonts suitable for non-Latin writing systems.
- [ ] Pseudo-localization testing passes in staging without clipping, truncation, or broken layout.
- [ ] CI pipeline validates that all user-facing strings are extracted into translation catalogs with no missing keys.
- [ ] Translation catalog entries include translator descriptions and placeholder context.
